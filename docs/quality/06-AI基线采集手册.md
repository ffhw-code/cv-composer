# AI 基线采集手册（harness 使用说明）

> 本文件是**操作手册**：测试会话跑 AI 采集时的用法、环境变量、守卫与卫生规则。
> 来源：早期交接文档 6.2 节（原文迁移，未改动任何取值）+ 早期 QA 报告（`TASK-014-I` 探针）+ `baseline/` 实际实现。
> 口径与红线见 `01-测量协议与判定阈值.md`；历史数据见 `04-AI链路与成本指标.md`。

## 一、涉及的文件

| 文件 | 作用 |
|---|---|
| `baseline/aiBaseline.run.ts` | 正式采集 harness（场景定义、预检、守卫、汇总、落盘） |
| `baseline/aiProbe.run.ts` | 请求形状探针（需显式开关 `AI_BASELINE_PROBE=1` 才发请求，防止正式采集顺带多花额度） |
| `vitest.ai-baseline.config.ts` | harness 专用 vitest 配置（只匹配 `baseline/**/*.run.ts`，**不影响 CI**） |
| `tsconfig.baseline.json` | harness 的 tsc 工程；改动 `baseline/**` 后必须过 `npx tsc -p tsconfig.baseline.json` |
| `metrics/` | 采集产物（JSON + 自动生成的 `.summary.md`），**本地未入库** |

**五个场景 id**：`generate-resume` / `add_module` / `set_content` / `set_style` / `tool-error-retry`。

## 二、命令速查

```bash
# 全量（5 类场景 × 5 次）——注意额度，一次约 250k tokens
AI_BASELINE_KEY='…' AI_BASELINE_MODEL=qwen3.7-flash npm run ai-baseline

# 单场景定向复现（推荐，省额度）
AI_BASELINE_KEY='…' AI_BASELINE_MODEL=qwen3.7-flash \
  AI_BASELINE_SCENARIOS=set_style,tool-error-retry \
  AI_BASELINE_ITERATIONS=3 AI_BASELINE_MAX_TURN_TOKENS=20000 \
  npm run ai-baseline
```

> ⚠️ 命令里的 Key 写法只是**占位示意**。真实执行时 Key 由环境变量 `AI_BASELINE_KEY` 提供，**绝不写进命令行、报告或任何文件**。

## 三、环境变量全表

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `AI_BASELINE_KEY` | 必填 | API Key，只经环境变量传入，不落盘（落盘前会擦除） |
| `AI_BASELINE_PROVIDER` | `aliyun` | 服务商预设 |
| `AI_BASELINE_MODEL` | `qwen-max` | **不指定就会用 `qwen-max`，在免费额度账号下必然 403** |
| `AI_BASELINE_BASE_URL` | 服务商预设 | 自定义端点（如 `https://api.deepseek.com`，官方端点**不需要** `/v1`） |
| `AI_BASELINE_ITERATIONS` | 5 | 每场景重复次数 |
| `AI_BASELINE_SCENARIOS` | 全部 | 逗号分隔；**写错会在模块顶层直接报错** |
| `AI_BASELINE_MAX_TURN_TOKENS` | 30000 | 单轮上限，超过即终止并落盘（标 `aborted`） |
| `AI_BASELINE_OUT_DIR` | `metrics` | **必须用绝对路径**（`/tmp/x` 在 WSL 下会被解析成仓库内路径） |
| `AI_BASELINE_PREFLIGHT` | 开 | 设 `0` 可关（离线验证守卫时用过） |
| `AI_BASELINE_PROBE` | 关 | 探针开关：不设时 `aiProbe.run.ts` 打印 `[skip]` 且不发请求 |

## 四、harness 的内建保护（都已实现，改 harness 时不要破坏）

1. **预检**：开跑前发一个最小请求（含 tools schema）验证网络与模型名 → 坏配置几秒内失败，不留脏文件。
2. **0 轮不落盘**：未设 Key 或全部请求失败时，**不产生** `metrics/` 文件（避免留下看着像基线的空文件）。
3. **污染标记**：传输层失败占比 > 20% 时，报告与摘要标 `suspect`。
4. **单轮守卫**：单轮 token 超 `AI_BASELINE_MAX_TURN_TOKENS` 或出现 `network` 类失败 → 立即终止、落盘已完成轮次、报告标 `aborted`。
5. **场景过滤**：`AI_BASELINE_SCENARIOS` 只跑指定场景，未知场景直接报错。
6. **每场景落盘**：跑完一个场景即落盘，中途中断也保留已采集数据。
7. **驱动方式**：`renderHook` 直接跑**真实** `useAiChat`；每轮重置为固定 id 的种子画布、清空埋点、新建会话 —— 因此采集到的请求形状**就是产品真实形状**。

**尚未实现（归 `P0.2` 第 6 项，落地后本节需更新）**：单场景有效轮数为 0 时标 `incomplete`（目前只看全局传输失败比例，`2fb9652` 那轮 15.8% 未触发 `suspect`，但 `add_module` 实际 0 数据）；总额度守卫 `AI_BASELINE_MAX_TOTAL_TOKENS`。

## 五、零成本自检（改完 harness 建议先做）

- 不设 Key 执行 → 预检阶段失败（退出码 1）且 `metrics/` 无新文件；
- 不设 `AI_BASELINE_PROBE=1` 执行探针 → 打印 `[skip]`，0 次请求；
- 用不可达网络端点执行 → 传输层全失败、token 0、`metrics/` 无新文件。

以上三条已在 `TASK-014-I` 实测验证过（见 `04-AI链路与成本指标.md` 第七节）。

## 六、采集前检查清单（每次真调模型前逐条确认）

1. 老板确认**本次预算上限**非 0；
2. 老板确认**对应渠道**（阿里云百炼 / DeepSeek 官方）的余额（两本账，互不相通）；

4. 自定义输出目录用绝对路径（`AI_BASELINE_OUT_DIR`）；
5. 发不发 `tool_choice` / 是否开思考，按当次档位的 quirks 策略（见 `04-AI链路与成本指标.md` 第七节）；

7. 结束核对：`suspect` / `incomplete` / `aborted` 标记如实保留，不粉饰。

## 七、`AI_BASELINE_KEY` 读不到时的排查（历史坑，2026-09-16 实测）

harness 预检阶段就会用到 Key；**Codex 会话是「非交互」方式执行命令**，如果变量只写在 `~/.bashrc` 里，会话可能读不到：
`~/.bashrc` 第 6–9 行有 bash 默认的「非交互即 return」守卫，非交互 shell 走到那里就返回了。

**自检命令**（在**运行 Codex 的那个终端**里执行）：

```bash
echo ${AI_BASELINE_KEY:+SET}
```

- 输出 `SET` → 正常，harness 可用；
- 无输出 → 见下面的排查顺序。

**排查与解法（按顺序试）**：

1. **打开一个全新的终端窗口**（不要复用旧标签页），先自检；确认 `SET` 后**从那个终端**启动 Codex
   —— 旧终端里的 shell 不会重新读 `.bashrc`，即便老板已经改过 `.bashrc`，那个终端里的 Codex 及其子进程也拿不到新变量；
2. 或者在旧终端执行 `source ~/.bashrc` 后再启动 Codex；
3. **兜底**：若重启后仍不可见，改由**老板本人在自己的终端代跑**（测试会话给出命令，命令里**不含** Key），产物交测试会话分析。

**禁止**：把 Key 直接拼进命令行交给 Codex 执行 —— 它会留在会话记录里，等同于泄漏（违反 `AGENTS.md` 第 9 节）。

> 历史背景：2026-09-16 曾因此卡住一次采集。当时同一会话里 `DEEPSEEK_API_KEY` 等其他变量是 `SET` 的，只有
> `AI_BASELINE_KEY` 读不到，说明**环境变量继承本身是通的**，问题只在于「Codex 进程启动的那个终端早于 `.bashrc` 的改动」。
