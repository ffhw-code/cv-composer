**冒烟口径（第 5 + 8 项一起验）**

- 场景：重设计后的 `tool-error-retry`，1 场景 × 1 轮（约 5 万 tokens）。
- **三条必查**：① HTTP 200；② 该轮至少出现一次 `tool_call`；③ 出现结构化工具错误返回（证明新输入真的命中「工具报错」链路）。
- 若第 ② 条不满足 → **不得**直接判失败或成功：先用 `add_module` 补 1 轮（约 1 万 tokens）区分「场景不可用」与「共用开关未生效」，再报老板。
- **本阶段不声称「自愈率提升」**：守卫生效的证据由 `P0.1` / `P0.3` 的 `redundant` 计数与单轮调用次数承担（自愈不在任何交付标准口径内）。

**归口说明**：`tool-error-retry` 场景重设计归 `P0.2`（0 token），**不**扩 `P0.1` / `P0.3` 的场景集（这两者 5 项指标 / 三条判定都能被 `add_module`、`generate-resume` 覆盖）；不采纳「扩到 3 场景」的落法，理由是省下约 15~20 万 tokens 与两份已拍板方案的改动，而自愈指标无交付标准消费者。

**保留**：`set_style` / `set_content` 对「刚创建 id」的既有窄守卫（`useAiChat.ts:337`）不删，只在其上补通用指纹守卫。

## 三、接口纪律与边界

- **不改 `argsStatus` 语义**（它只描述参数解析结果）；冗余一律走 `errorKind`，**复用已有的 `'redundant'`**（`src/utils/aiMetrics.ts:31`），不新增枚举值。
- 指纹 = `工具名 + ':' + stableStringify(args)`；`stableStringify` 需**按键名排序、剔除 `undefined`、数组保序**（数组顺序有语义）。
- 合法的「先 `remove_module` 再 `add_module`」指纹不同，**不得误拦**；批量改同一模块的不同属性参数不同，安全。
- 模型自造随机 id 时指纹不同，指纹守卫拦不住 —— 靠 `add_module` 的「同名模块已存在返回 `REDUNDANT_MODULE`」兜底。

本小阶段收口即**冻结生效**：此后到总收口不得再改工具 schema、system prompt 的约束块（`src/engine/ruleBase.ts` 的 `getFixedConstraints`）、轮次上限语义。

## 六、残余风险

- schema 收敛会改变请求形状 ⇒ 与历史 AI 数据不可比，只能靠 `P0.3` 重采；
- 指纹守卫拦不住「同语义不同取值」的重复调用（换成自造的新 id、换个措辞），只拦「同工具 + 等价参数」（参数键序不同不算不同）；这是已知边界，本阶段不扩大范围；
- `duplicate_module` 同参数连调两次会被判冗余（想复制两份时应复制「副本的 id」）——这是守卫的既定行为，靠回传的 `priorResult`（含新模块 id）让模型自己走下去；
- 假成功防护最多追加 1 次纠正请求；纠正仍不改口时只把提示显式写给用户，**不再重试**（避免无限空转烧额度）。命中过假成功的这一轮 `outcome` 记 `partial`（哪怕随后纠正成功）。
