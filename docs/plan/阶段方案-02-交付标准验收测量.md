## 一、阶段目标

把老板已拍板的**四项交付标准**从「口径」变成「**可引用的实测结论**」：标准 1 与标准 3 判二档是否达标、标准 2 判一档（关键字段 ≥90%、版式结构一致度 ≥80%）是否达标、标准 4 出一轮主观评估。

**本阶段是唯一「花钱」的阶段**：合计约 **350 万 ~ 430 万 tokens**（见第六节）。

## 三、逐项方案

### 测量项 2｜CP-1 可达性检查点（**建议最先做**）

**为什么最先做**：时段 E（交付标准 2 复刻改造）估 **40~84 h**，是唯一「投入工时也不能保证结果」的时段。CP-1 是**唯一能提前判定一档是否可达**的动作。

- **内容**：取 2 张真实简历图，各跑「现状单步调用」与「两步流程（先提文字再构建版面）」各 1 轮，对比关键字段准确率。
- **成本**：3~5 h ＋ 约 4~8 万 tokens。
- **决策规则**：若两步流程能把字段准确率**显著拉向 90%** → 全力投入时段 E；若差距仍大 → **当场请老板重新商定「1:1 复刻」口径**，而不是先烧掉 40~84 h 再发现达不到。

### 测量项 3｜工具指令集采集（标准 3）

- **测试集**：26 个工具各 1~3 条中文指令；**复用 `baseline/` harness 采集，禁止另造一套**。
- **指标 A**：工具级正确调用率；**指标 B**：结果级成功率。
- **规模**：26 工具 × 3 轮 = **78 轮/次**，至少 3 次（改前、改后、一档冲刺复测）。
- **额度**：约 **78 万 tokens/次**（qwen 档位，约 1 万/轮）或约 **420 万 tokens/次**（DeepSeek 档位，实测约 5.4 万/轮）。**预算需按实际档位重算，采集期间不得中途换档。**
- **档位定义待老板确认**（未确认前无法判定「是否达标」）。

### 测量项 4｜复刻测试集采集（标准 2）

- **测试集**：≥5 张真实简历图，至少覆盖「单栏 / 双栏 / 时间线式 / 含照片 / 多页」各 1 张。模板由工作会话起草，**图片与字段标准答案由老板提供**。
- **指标 A**：关键字段准确率 = 提取正确的关键字段数 ÷ 关键字段总数。关键字段：姓名、联系方式、每段经历的「公司 / 职位 / 时间」、教育的对应字段等。
- **指标 B**：版式结构一致度（5 子项 0 / 0.5 / 1 打分）。
- **指标 C**：人工可修正成本。
- **一档口径**：指标 A ≥90%、指标 B ≥80%。
- **规模**：5 图 × 3 次 = **15 轮/次**，图片请求按 1.5~2.5 万 tokens/轮 ≈ **22~38 万/次**，迭代约 5 次。
- **视觉档位**：已实测 `deepseek-flash` 支持图片输入（1×1 PNG 探针 HTTP 200 并正确识别）；当前预设另有 `qwen-vl-max`。

### 测量项 5｜手动操作清单（标准 1，老板执行）

- **执行人**：老板。固定浏览器与分辨率、固定步骤、每步写「预期 / 实际」。
- **覆盖范围（至少）**：新增与嵌套模块、拖动排序、跨页分页边界、溢出自动缩放、撤销重做、导出。
- **代理指标（0 token，可自动复跑）**：
  - 画布状态摘要耗时（AI 每轮必跑的热路径）：历史基线 **23.2 µs**，该 bench 噪声跨度 33%，阈值 > 35%，**只作趋势参考**；
  - 布局幂等性：同一操作序列重复执行后 `exportLayoutTree` 结果是否逐字节一致（精确值，可做成单元测试）；
  - 产物体积与用例数（精确值指标）：**用例数不得低于当时基线**；
  - 构建 / 测试 / lint 墙钟（辅助指标，按 `docs/quality/01` 第四节阈值判定）。
- **通过条件**：M 清单全项通过，且代理指标无超过噪声阈值的劣化；有变化必须逐条解释。

### 测量项 6｜主观评分表（标准 4）

- **维度**：5 个维度，1~5 分。
- **样本**：≥5 份简历，每份 ≥3 条建议；评分人 = 老板（可选再加 1 人）。
- **只做一轮**；报告中**必须写明「主观数据」**，不得与客观指标混算或作为优化结论。

## 四、工时估算（本阶段相关时段）

口径：人·小时，**估算值、未实测**，不含「等老板传话」的等待时间；四项全绿约 35 秒，可忽略。

| 时段 | 内容 | 估算 |
|---|---|---|
| C | 交付标准 1：清单起草 + 老板执行 + 代理指标落地 + 缺陷修复预算 | 14~26 h |
| D | 交付标准 3：指令集构造 + 采集 + schema 瘦身 + 修复 + 复测 + 一档冲刺 | 31.5~57 h |
| E | 交付标准 2：测试集模板 + CP-1 + 复刻流程改造 + 3~6 轮迭代 | 40~84 h |
| F | 交付标准 4：评分表 + 老板评分 + 归档 | 3~4 h |

**关键路径 = 时段 E（交付标准 2）**，40~84 h，且是唯一「投入工时不能保证结果」的时段。
**全项目汇总**：乐观约 **110 h**，悲观约 **210 h**。

## 五、执行顺序（建议）

```
（阶段 1 收口 + 标准 1 / 3 档位定义拍板）
  → 测量项 2 CP-1（3~5 h + 4~8 万 tokens）→ 老板据此决定标准 2 是否继续投入
  → 测量项 5 标准 1 手动清单（老板执行，0 token）
  → 测量项 1 改后全量复跑（约 250k tokens）→ 作为标准 2 / 3 的测量基线
  → 测量项 3 标准 3 工具指令集采集 → 修复 → 复测
  → 测量项 4 标准 2 复刻测试集采集 → 迭代 3~6 轮
  → 测量项 6 标准 4 一轮主观评分
```

## 七、前置条件（缺一不可）

1. **阶段 1 收口**（否则测的是会变的行为）；
2. **老板确认对应渠道余额**（DeepSeek 官方 / 百炼分别确认）；
3. **标准 1 / 标准 3 的档位定义拍板**（不拍板则无法判定这两项「达标」）；
4. 标准 2 需要老板提供 ≥5 张真实简历图与字段标准答案；标准 4 需要老板评分；标准 1 需要老板执行 M 清单。
