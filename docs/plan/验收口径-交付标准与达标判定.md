## 二、四项标准的可测化口径（原文搬出，逐字未改）

原则：先定义测量方式，再定执行方案；口径真源是 `docs/quality/01-测量协议与判定阈值.md`，本节只做「交付标准 → 可测项」的映射，不新造测量协议。

### 交付标准 1：基础编辑稳定、流畅、可扩展；画布准确、灵敏直观；网页文档流自动排版

测量方式由两部分组成：

1. **手动操作清单（M 清单，PM 起草、老板执行、QA 留痕）**：固定浏览器与分辨率、固定步骤、每步写「预期 / 实际」。起草时至少覆盖：新增与嵌套模块、拖动排序、跨页分页边界、溢出自动缩放、撤销重做、导出。
2. **代理指标（0 token，可自动复跑）**：
   - 画布状态摘要耗时（AI 每轮必跑的热路径）：历史基线 23.2 µs，该 bench 噪声跨度 33%，阈值 > 35%，只作趋势参考。
   - 布局幂等性：同一操作序列重复执行后，`exportLayoutTree` 的结果是否逐字节一致（精确值，可做成单元测试）。
   - 产物体积与用例数（精确值指标）：任何字节/用例数变化都真实，但**用例数不得低于当时基线**。
   - 构建、测试、lint 墙钟（辅助指标，按 `docs/quality/01-测量协议与判定阈值.md` 第四节阈值判定）。

通过条件：M 清单全项通过，且代理指标无超过噪声阈值的劣化；有变化必须逐条解释。

档位定义（PM 制定的可验收口径，待老板确认）：

| 档 | 判定内容 |
|---|---|
| 二档（老板指定为「必须达标」） | M 清单全项通过；构建体积与用例数无劣化（用例数不得低于当时基线）；布局幂等性有自动化测试且通过 |
| 一档（可选冲刺） | 在二档基础上，画布状态摘要热路径（历史基线 23.2 µs）优化幅度超过该 bench 的 35% 噪声阈值；60 模块规模简历的操作无可感知卡顿（由老板手动确认） |

### 交付标准 2：AI 解析简历图片、接近 1:1 复刻到画布

1. **测试集**：≥5 张真实简历图片，至少覆盖「单栏 / 双栏 / 时间线式 / 含照片 / 多页」各 1 张。模板由 PM 起草，图片与字段标准答案由老板提供。
2. **指标 A 关键字段准确率** = 提取正确的关键字段数 ÷ 关键字段总数。关键字段：姓名、联系方式、每段经历的「公司 / 职位 / 时间」、教育的「学校 / 专业 / 时间」。
3. **指标 B 版式结构一致度** = 5 个子项各 0 / 0.5 / 1 分后取平均：模块顺序、栏数、对齐方式、层级（标题与正文区分）、模块分组是否与原图一致。
4. **指标 C（次要）人工可修正成本**：复刻后仍需手工调整的模块数。
5. 记录项：模型档位、token 成本、同图重复 3 次取中位数（模型输出有随机性）、失败样本原样保留。

档位定义见下方「标准 2 的三档口径（老板已定一档）」。

**标准 2 的三档口径（原文搬出，仅把「见第九节」改为「见第三节」）：**
**老板选定：一档 ＝ 关键字段准确率 ≥ 90% 且版式结构一致度 ≥ 80%。**
**工期口径变更：一律以「小时」计，不使用「周」（老板 2026-09-16 指定）。** 工时估算见第三节。


| 档 | 关键字段准确率 | 版式结构一致度 | 代价与工期 |
|---|---|---|---|
| 一档（**老板选定：必须达标**） | ≥ 90% | ≥ 80% | 需改 prompt + 很可能引入两步流程（先提文字再构建布局）+ 服务端图片/文档预处理，约 40~85 小时（估算值，未实测） |
| 二档 | ≥ 80% | ≥ 60% | 主要靠 prompt 与示例补强，约 20~35 小时（估算值） |
| 三档 | ≥ 70% | ≥ 50% | 允许带缺陷上线、人工快速修正，约 10~18 小时（估算值） |

仍待老板拍板的事项：一档目标**存在技术不确定性**（取决于视觉模型能力上限与简历版面多样性），PM 无法承诺「投入固定工时即可达成」。PM 建议先做一个 3~5 小时的**可达性检查点实验**（见第三节 CP-1），用真实结果决定是全力冲刺一档，还是与老板重新商定口径。
（另：`TASK-014-I` 探针已实测**该档位支持图片输入**，见 `docs/quality/04-AI链路与成本指标.md` 第七节。）

### 交付标准 3：AI 助手会使用编辑器的全部编辑操作

1. **工具清单**：`src/engine/aiPrompt.ts` 当前定义 26 个工具（含 `execute_skill` 与查询类）。
2. **指标 A 工具级正确调用率** = 「调用了期望工具且参数可用」的指令数 ÷ 该工具指令总数。每个工具构造 1~3 条中文指令。
3. **指标 B 结果级成功率** = 该轮结束后画布实际结果与预期一致的比例（防止「调用了但没改对」）。
4. **门槛建议**：核心写操作工具 ≥90% 工具级正确调用率；查询 / 导出 / `execute_skill` ≥70%。

档位定义（PM 制定的可验收口径，待老板确认）：

| 档 | 工具级正确调用率 | 结果级成功率 |
|---|---|---|
| 二档（老板指定为「必须达标」） | 核心写操作工具 ≥90%；查询 / 导出 / `execute_skill` ≥70% | ≥70% |
| 一档（老板指定为「尽量达标」） | 全部 26 个工具 ≥90% | ≥85% |
5. **成本警示**：26 工具 × 3 轮 ≈ 78 轮 ≈ 800k tokens，远超当前剩余额度。必须分批、必须复用现有 harness 并启用总额度守卫。

### 交付标准 4：AI 助手是简历专家，能给出建议与优化

1. **主观评分表**：维度 5 项（问题识别准确性、建议具体性、可执行性、排版建议合理性、整体有用性），1~5 分制。
2. **样本**：≥5 份简历，每份 ≥3 条建议；评分人 = 老板（可选再加 1 人）。
3. **标注要求**：报告中必须写明「主观数据」，不得与客观指标混算或作为优化结论。

先做最简单的后端，AI 体验优化达标后再逐步完善。量化结论：

1. **模型路由与降级**（服务端）→ 决定交付标准 3 能否从二档冲一档（实测换更强模型可让 `set_style` 从「48 次调用 47 次参数不可用」变成「3/3 全对」）。

其余影响（API Key 暴露在浏览器、成本与指标只存在本机 `localStorage`、简历数据不留存）属**上线与商业化**问题，不改变 AI 效果本身。
方案清单（B0~B4）见 `docs/plan/阶段方案-04-后端B3.md`。
